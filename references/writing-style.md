# 行文风格与格式细则

## 语言与术语

- 正文用中文；术语首次出现写"中文（English, ABBR）"，之后可用缩写。例：间接提示注入（Indirect Prompt Injection, IPI）。
- 人名、模型名、数据集名、工具名、函数名、参数字母保留原文，不翻译：Gemini-2.5 Flash、AgentDojo、`HIERATTENUATE`、`λ`。
- 代码、变量、函数、阈值用反引号；论文原文的关键措辞用引号直接引用，例如作者用 "what" / "why" 的对立概括范式转移。
- 论文自造的概念第一次出现时给出英文原名，后续用中文短名。

## 结构与语气

- **倒金字塔**：每节先给结论或要义，再展开机制与证据。
- 关键结论、机制名、转折点用加粗标出：**攻击面**、**唯一**、**主分支负责把事做好，影子分支负责安全检查**。
- 段落之间要有推进关系（背景 → 不足 → 转向 → 机制 → 证据 → 边界），不要把论文的并列段落原样搬过来。
- 遇到论文用反问自问自答的地方，保留这种张力：**"为什么不干脆只用衰减视图执行（省掉影子分支）？"** 然后逐条给出论文的回答。
- 批判要落到机制上：指出在哪一步失效、为什么失效、代价落在谁身上。避免"实验充分""方法新颖""值得借鉴"这类空话。
- 数字、阈值、比例、样本量一律给全，并保持与论文一致（"ASR = 0%"、"92 个用户任务 + 882 个攻击实例"、"λ = 2"）。

## 排版

- 顶层 `##` 小节之间用 `---` 分隔。
- 对比、映射、清单类信息用表格：`范式 | 代表工作 | 主要贡献`、`挑战 | 问题描述 | 对应设计`、`模型 | 维度`。
- 并列要点用列表；因果链、机理分析、论证过程用自然段。
- 表格表头简短；需要强调的单元格可以加粗；表格各行的竖线对齐不强制。
- 中文标点，数字与单位用半角；不要用全角括号包英文术语。
- 图片单独成行，紧跟一段说明它在讲什么。

## 可复用的段落写法

- **摘要 · 主要目的**：先点出现有范式的根本缺陷（"……的根本缺陷在于把 X 建模为 Y"），再给本文的转向（"因此转向……"）。
- **现有研究的不足**：分类 → 每类的隐含假设 → 假设为何脆弱 → 论文用什么证据证伪它。
- **核心组件**：解决什么失效 → 机制怎么做 → 论文给的例子或公式 → 为什么不是更简单的做法。
- **RQ 小节**：设置（第一句，写全数据集 × 模型 × 攻击 × 预算）→ 结论 → 数字 → 图 → 异常与解释。
- **局限**：局限是什么 → 在什么场景被放大 → 论文给的缓解路径（没有就直说）。

## 语气锚点（摘自参考笔记，仅作风格示例）

> 作者认为现有防御的根本缺陷在于把安全建模为**输入空间的语义判别任务**（"what"）……因此转向**动作空间的因果归因**（"why"）。

> **AttriGuard 的分离设计**：**主分支负责把事做好，影子分支负责安全检查。**

> 一个隐蔽的误报源是**批处理方差**。

> 消融实验表明三个核心组件各自负责安全与效用折中的不同侧面、缺一不可。

## 反面清单

- 不要逐段翻译论文；不要把摘要抄成笔记。
- 不要写成读书报告式的"本文提出……本文还提出……"流水账。
- 不要在个人反思里复述论文结论；那里只放自己的判断。
- 不要留下占位符、待办标记或未完成的句子。
