# 笔记大纲与各节要求

这份大纲来自用户已归档的参考笔记，层级、顺序和栏目标题都按它保持一致。论文结构不同时，可以增删 `###` 小节，但不要改动顶层 `##` 的顺序与名称。

## 骨架

```markdown
# <短名> 论文笔记

> 原文：*<论文完整标题>*
> 阅读版本：<会议/年份/页码或页数>

---
```

## 各节要写什么

**摘要（Abstract）** — 用自己的话重述论文的摘要，四段各有分工：主要目的写"现有范式的缺陷 + 本文的转向"；方法写核心机制（组件名要中英并列）；结果写关键数字（数据集、模型数、ASR/效用、对比方法数）；结论要一句话收束主张。这一节是全文的压缩版，读者只读这里也应该拿到要点。

**引言 · 研究背景与问题** — 交代问题为什么值得做：新的能力带来什么新的攻击面、威胁的实际后果（引用论文给的案例）、以及问题的量级（标准排名、真实事件）。把论文里的一句话背景展开成有因果的叙述。

**引言 · 现有研究与其不足** — 按范式分类现有工作，**每个类别都要写出它的隐含假设，再写这个假设为什么脆弱**。结尾用表格汇总：`范式 | 代表工作 | 主要贡献`。这是全文最见功力的部分，不要只罗列方法名。

**引言 · 主要贡献** — 通常 3 条，对应论文的 contributions，但要写成"结论 + 支撑"的形式，而不是照抄原文列表。

**方法 · 威胁模型** — 分三块：攻击者能力与知识（能做什么、知道什么，有无自适应版本）、防御者能力与知识（可拦截什么、是否黑盒）、**显式非目标**（论文明确不处理的情形）。非目标一定要写，它界定了方法的适用边界。

**方法 · 系统总览** — 先插入总体架构图（`image-N`），再用一段话按步骤讲清运行时流程；关键术语用加粗标注。这里的顺序要与图一致。

**方法 · 核心组件** — 每个组件一个小节。固定写法：这个组件解决什么失效 → 怎么实现 → 论文给的例子/公式/算法（该插图就插图）→ 为什么不是更简单的做法。论文如果自己回答了"为什么不那样做"，一定要保留。

**方法 · 完整算法** — 插入算法伪代码图，然后写：核心思想（一句话）、流程要点（逐条）、符号说明（列表，逐项解释正文用到的记号）。

**实验 · 实验设计** — 依次写：数据来源/基准（含被剔除的样本数和原因）、骨干模型（**给表格**，标注开源/闭源、推理型/标准型）、攻击类型、对比方法（**给表格**，按范式分组）、评测指标（给出定义）、实现细节（超参、重复次数、随机性来源）、研究问题清单（RQ1…RQn）。

**实验 · RQn** — 每个 RQ 独立小节，标题写成 `### RQn：<这个 RQ 在问什么>`。固定结构：**第一句写设置**（数据集 × 模型 × 攻击 × 预算/重复次数）→ 结论 → 关键数字（用加粗突出）→ 插入对应结果图（一图一段）→ 异常与作者的解释。数字要写全（如"唯一在四类攻击上都是 0% ASR 的方法"），不要含糊成"效果很好"。

**结论 · 主要结论 / 研究贡献 / 局限与未来工作** — 主要结论用有序列表（3 条左右）；研究贡献按**概念 / 技术 / 实证 / 实践**分类；局限要逐条写清"局限是什么 + 作者给的缓解路径"，作者没有缓解路径就写"论文未给出"。

**个人反思** — 这是笔记与论文摘要的分水岭，必须有自己的判断：

- 论文优点 / 缺点：各 3 条上下，每条一句话点题 + 两三句展开。缺点要落到具体机制上（"某个安全组件本身建立在可被注入的模型之上"），不要写"样本量可以更大"。
- 论文难点：**表格** `挑战 | 问题描述 | 对应设计`，把论文中"实际困难 → 设计选择"的映射抽出来。
- 与自己研究的关联：结合用户的研究方向谈这篇论文可迁移或可质疑之处。
- 最有价值的点：列论文里最值得带走的 1–5 个想法，说明为什么它们**超出本文具体实现**仍然成立。
- 对当前课题的启发：给可执行的研究动作或评测建议。

## 图片与表格的分配

- 每张 `image-N` 都要在正文里被解释，并尽量与上下文形成"看图 → 读结论"的配合，不要堆在文末。
- 优先顺序：方法架构图 → 算法/伪代码 → 主结果图 → 消融图 → 自适应攻击/鲁棒性图。
- 论文的表格通常改写成 markdown 表格；只有结构复杂或信息依赖颜色/排版时才抽成图片。
- 自绘图（mermaid / plantuml / markdown 表格）用于概括论文没有直接给出的结构，例如"现有防御范式分类""RQ → 结论映射"。不要用自绘图替代可以直接提取的原图。

## 篇幅

深度跟着论文体量走。参考笔记对应的是一篇 21 页论文，正文约 1.3 万字。信息密度优先：宁可短而准，也不要长而空。
